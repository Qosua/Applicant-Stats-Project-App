# Руководство по оформлению комментариев

Документ описывает соглашения по комментариям проекта (Qt / C++ / QML). Новый код желательно оформлять так же, чтобы стиль оставался единым.

## 1. Общие правила

- **Язык:** комментарии пишутся на русском. Идентификаторы и технические термины (`QThread`, `CacheManager`, `QML`) остаются как есть.
- **Стиль:** только однострочные `//` и `///`. Блочные `/* ... */` не используются.
- **Пробел:** после `//` и `///` всегда ставится один пробел.
- **Длина строки:** примерно до 100–110 символов. Длинный комментарий переносится на следующую строку с тем же отступом.
- **Что описывать:** не пересказывать код, а объяснять *зачем* он нужен и *что произойдёт в результате*.
- **Актуальность:** при изменении кода комментарий обновляется в том же коммите.

## 2. Документирующие комментарии функций

Перед каждой свободной функцией (и методом) ставится блок `///`:

1. краткое описание назначения;
2. по одной строке `@param` на каждый параметр;
3. Другие `@...` (опционально)
4. строка `@return`.

### Шаблон

```cpp
/// Краткое описание: что делает функция и для чего она нужна
/// @param Тип& имяПараметра описание параметра (по необходимости)
/// @return Тип
void functionName(Тип& имяПараметра) {
    ...
}
```

### Пример из проекта

```cpp
/// Метод нужен просто для компактности кода
/// @param QmlHelper& qmlHelper
/// @param CacheManager& cacheManager
/// @param TreeViewModel& treeViewModel
/// @param StatsPageModel& statsPageModel
/// @return void
void connectSignals(QmlHelper& qmlHelper, CacheManager& cacheManager, TreeViewModel& treeViewModel,
                    StatsPageModel& statsPageModel) {
```

### Правила

- Формат параметра: `@param <Тип> <имя> [описание]`. Тип указывается так же, как в сигнатуре (со ссылкой `&` и `const`).
- Описание параметра обязательно, если его назначение неочевидно из имени.
- `@return` указывается всегда, даже для `void`.
- Описание начинается с заглавной буквы, точка в конце не обязательна.
- Продолжение параметров в сигнатуре выравнивается по первому параметру.

### Пример с описанием параметров

```cpp
/// Метод нужен для первичной инициализации CacheManager в другом потоке
/// @param QThread& thread объект потока, в который передаём CacheManager
/// @param CacheManager& cacheManager сам CacheManager
/// @return void
void moveToThread(QThread& thread, CacheManager& cacheManager) {
```

## 3. Строчные комментарии над кодом

Комментарий пишется **на отдельной строке над** тем кодом, который он поясняет, с тем же отступом.

```cpp
// инициализация объекта в потоке после старта самого потока
QObject::connect(&thread, &QThread::started, &cacheManager, &CacheManager::init);
```

- Многострочный комментарий — несколько подряд идущих строк `//`.
- Между комментарием и кодом пустых строк нет.
- Допустимо начинать с маленькой или с заглавной буквы, но внутри одного блока стиль должен быть единым. Для коротких пояснений в одну строку используется строчная буква, для развёрнутых описаний — заглавная.

## 4. Комментарии сигналов и слотов

Каждый `QObject::connect` сопровождается комментарием, который отвечает на три вопроса:

| Вопрос | Что указать |
|---|---|
| Откуда сигнал? | источник (QML, конкретный менеджер) |
| Что передаётся? | суть данных или события |
| Что происходит дальше? | какой слот и какой результат |

```cpp
// Сигнал поступает из qml с информацией о нахождении файла таблицы, которую надо обработать
// в CacheManager, где будет дальше решено, что делать с таблицей
QObject::connect(&qmlHelper, &QmlHelper::sendSignalToProceedTable, &cacheManager,
                 &CacheManager::processTable);
```

Если один сигнал подключён к нескольким получателям, комментарий дублируется перед каждым `connect`, но заканчивается указанием на конкретного получателя:

```cpp
// После успешной обработки таблицы отправляется сигнал sendProceededData с результатом обработки.
// Результат устанавливается в модель древесного представления
QObject::connect(&cacheManager, &CacheManager::sendProceededData, &treeViewModel,
                 &TreeViewModel::setFaculties);

// После успешной обработки таблицы отправляется сигнал sendProceededData с результатом обработки.
// Результат устанавливается в модель страниц статистики
QObject::connect(&cacheManager, &CacheManager::sendProceededData, &statsPageModel,
                 &StatsPageModel::setFaculties);
```

Перенос аргументов `connect` выравнивается по первому аргументу.

## 5. Разделители секций

Крупные блоки в `main()` отделяются заголовком-разделителем:

```text
//----Название секции----------------------------------------
```

### Формат

- Начало: `//` + четыре дефиса `----`.
- Затем название секции без пробелов вокруг.
- Далее дефисы добавляются так, чтобы все разделители в файле имели **одинаковую длину** (около 65 символов).
- После разделителя идёт код секции; перед следующим разделителем — пустая строка.

### Пример

```cpp
//----Система логирования----------------------------------------
Logger::initLog();
qInstallMessageHandler(Logger::logHandler);

//----Системные утилиты------------------------------------------
AppPathsManager::init();
DataBaseManager::instance().init();

//----Потоки ----------------------------------------------------
QThread cacheThread;
```

## 6. Концевые (trailing) комментарии

Для коротких пояснений к однотипным строкам (инициализация, объявление объектов) используется комментарий **в конце строки**.

Требования:

- комментарий начинается с `//` и строчной буквы;
- текст — краткий, описывает роль объекта, а не повторяет его имя;
- `//` во всех строках блока выравниваются в одну колонку (пробелами);
- выравниваются также типы и имена переменных в блоке объявлений.

### Инициализация

```cpp
AppPathsManager::init();            // менеджер путей
DataBaseManager::instance().init(); // менеджер БД
```

### Объявление объектов

```cpp
QmlHelper                qmlHelper;       // коллекция методов для qml (не объединённых в одну логическую группу)
CacheManager             cacheManager;    // менеджер кэша и обработки таблиц
TablesListModel          tablesListModel; // модель списка таблиц для qml
QSortFilterProxyModel    proxyModel;      // та же модель, что и выше, но с возможностью сортировки содержимого
TreeViewModel            treeViewModel;   // модель древесного представления иерархии факультетов и направлений
StatsPageModel           statsPageModel;  // модель страниц статистики
EntryCommisionsListModel entryModel;      // модель списка доступных правил приёма (приёмных комиссий)
ProgressHandler          progressHandler; // контроллер состояния прогресс-бара
ThemeManager             themeManager;    // менеджер визуальной темы
```

Уточнения и оговорки допускаются в круглых скобках в конце комментария.

## 7. Комментарии к группам однотипных вызовов

Если несколько подряд идущих строк делают одно и то же (например, `setContextProperty`), комментарий ставится **один раз над группой** и объясняет общий смысл, а при необходимости — даёт аналогию в скобках:

```cpp
//----передача объектов для qml в его контекст (можно воспринимать как глобальную область видимости)
engine.rootContext()->setContextProperty("sortFilterProxyModel", &proxyModel);
engine.rootContext()->setContextProperty("tablesListModel", &tablesListModel);
engine.rootContext()->setContextProperty("qmlHelper", &qmlHelper);
```
